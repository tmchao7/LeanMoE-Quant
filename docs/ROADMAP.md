## 1. 总体评估

### 1.1 相对目标的达成度

目标回顾：**本科生私下项目、投递推理优化 / AI 编译器 / HPC / 算子优化实习岗，
工程达标即可，不追求 SOTA**。按这个标尺分维度评：

| 维度 | 评价 | 依据 |
| --- | --- | --- |
| 正确性工程 | ★★★★★ | 门禁机械（schema 强制、`1e-3` parity、规则 9 自动归档）；38 个测试文件、**657 passed**（2026-10-23 实测）；精度三链闭合（KL / PPL / MMLU） |
| 性能叙事 | ★★★★☆ | 五条杠杆各有**同轮 A/B**（执行轴 2.43×、量化 1.1911×、注意力 1.3034×、融合 norm 1.2358×、投影修复 8.14→5.15 µs）；最有价值的是**实测出结构性上限 1.74× 并把九成归因到单 kernel**。扣分：单卡 batch=1、1B 激活，外推性有限（每份 payload 自带 applicability 声明） |
| 方法论可复核 | ★★★★★ | 每个数字带出处；金丝雀 + VOID 判废（已主动废过三轮）；负结果一等公民（E2 被否证、`F.rms_norm` 慢 5%、ncu 被宿主阻断均在档）；2026-10-10 三路深审又机械化了两处纪律漏洞 |
| 技术深度边界 | ★★★☆☆ | 4 个 Triton kernel 族齐全，但无 CUDA C++/手写 PTX、无 Tensor Core 路径（M=1 带宽受限下**刻意**不用，理由已文档化）；量化已从 per-group RTN 扩到 GPTQ + 校准集（EXP-p1-05 实测：4-bit 仍过不了门，负结果）；ncu 计数器被宿主策略阻断 |
| 呈现与投递 | ★★★★☆ | RESULTS / PORTFOLIO（简历定稿 + 面试三题）齐备；README 投递首屏与 G2/G3 可选 bullet 已于 2026-10-10 完成 |

### 1.2 最值钱的三点（面试叙事就讲这三个）

1. **测出了"天花板"而不是只报加速比**：量化上限 1.74×（权重仅占一步 42%）是实测推出来的，
   九成收益定位到专家 GEMV（1.52× 解释步级 90.4%）——这是分析深度，不是跑分。
2. **负结果与阻断一等公民**：融合反量化被 eager 格否证、torch 原生 norm 反而慢 5%、
   ncu 被宿主拒绝后交出替代口径——说明判断力与诚实，而不是只贴好看的数。
3. **纪律是机械的不是嘴上的**：门 FAIL ⇒ 性能字段自动进 evidence、覆盖前自动归档、
   金丝雀漂移判 VOID、480 个测试钉住这些行为——工程文化的直接证据。

### 1.3 主要短板（诚实清单，面试被问再展开）

- **规模与外推**：batch=1 单流、单卡、1B 激活；无 req/s、无并发、无服务侧调度（有意为之，见 RESULTS 适用范围表）。
- **量化算法边界已实测但很窄**：RTN per-group 对称 + 已实现 GPTQ/校准集；4-bit 在两道门前失败（EXP-p1-05），所以卖点仍在执行与评估闭环，不在算法新颖度。
- **统计效力**：MMLU n=200（SE≈3.5 点），−1.0 点的 PASS 在**口径内成立但与 2 点门槛统计上不可分辨**——引用时要带这句。
- **工具链缺口**：无 ncu stall/occupancy 归因（`docs/reference/NCU_PLAN.md` 是换机清单）。
- **流程残留（2026-10-10 深审结论）**：轮次金丝雀 VOID 判定**非机械**（只有 `batch_sweep` 在代码里判，其余靠脚本/人工）；graph 格的 p99 算在块均值上、与 eager 逐步样本**不可跨臂比**（已写入 METRICS 口径，p50 差 <1% 不翻案）。
- **矩阵未跑**：FP8/MXFP4、E5/E6/E8、dense 曲线、量化×batch 衰减对比（W4A16 已判负，见 EXP-p1-05；状态以 RESULTS §6 缺口表为准）。

### Tier C — 技术栈升级（对准 PORTFOLIO §4 的岗位缺口）

| # | 方向 | 补哪个岗位的缺口 | 说明 |
| --- | --- | --- | --- |
| C1 | **torch.compile vs 手工融合对照** | AI 编译器（最弱项） | 最小闭环：同一 norm/反量化场景，compile 图优化 vs 手写 Triton 的 A/B；把"融合与图捕获边界"的认知从经验变成数据 |
| C2 | **GPTQ/AWQ vs RTN 对照**（GPTQ ✅ 2026-10-23 负结果；AWQ 未做） | 量化岗 | 同一模型同一门下比 PPL/KL；把"算法简单"的短板变成"知道边界在哪"的证据 |
| C3 | **Tensor Core MMA 最小 kernel** | 算子岗 | 现在"不用 MMA"的理由是 M=1 带宽受限（已文档化）；加一个 batch>1 下 MMA vs 向量路径的对照，论证就完整了 |
| C4 | autotune/配置扫描工具化 | 算子岗 | `tools/bench_dequant_gemm_graph.py` 已有雏形，抽成通用扫描器 + 结果表 |
| C5 | 图捕获边界自动检测 | 推理优化岗 | 把 `MOE_CUDAGRAPH.md` 里的检测方法（数据依赖 shape 等）做成 load-time 检查器 |
| C6 | 极端分位 Δp 分析 | 量化岗加分 | llama.cpp 体系里的 1%/0.1% 分位口径——离线从已有 logits 工件算，不需新上机 |

### Tier D — 明确不做（保持定位，别临时加戏）

- **服务侧 / 连续批处理 / 多卡并行**——与 MegaKernel-vLLM、MoE-Flow 的分工冲突；
  本项目的价值恰恰是 batch=1 的纯净字节预算问题。
- **追 SOTA 量化算法**——卖点在执行与评估闭环；套一个新算法反而稀释叙事。
- **绕过 ncu 宿主限制**——已按诚实条目入缺口表，替代口径已交付；不要为了"完整"造假需求。

## 3. 优先级建议（如果只做五件事）

1. **F1 采纳三项已测融合**（`FUSION_OPPORTUNITIES.md` §F1）：代码已写、A/B 已测、默认关，
