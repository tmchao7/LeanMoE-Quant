## 2. 本轮（本地）改了什么，为什么

1. **`packed_qkv` 的两个前置（阻断级）**：`run_cudagraph` 原来对 `attn != kernel` 直接 raise，
   `run_baseline` 对 eager 臂直接 raise。采纳把默认翻成 `True` 之后，那两处会让**23 格刷新里的
   21 格 + 全部 eager 基线格**失败。现在：`packed_qkv_applicable(attn, quantized)` 为假 ⇒
   **不安装（no-op）**，不报错；payload 同时记 **请求**（`config.packed_qkv`，与另外三个开关对称）
   和 **生效**（`config.packed_qkv_effective`）。显式请求的 A/B 工具仍拒绝（不能量出一个假的 0%）。
2. **刷新脚本的断点条件是错的**：旧写法要求"四个开关全 True"才算已刷新，而 F2 只作用于 2 格
   ⇒ 其余 21 格永远满足不了，断点续跑会整轮重来。现在按**本格期望值**判断（6 种 payload 形态
   已离线验证）。
3. **刷新脚本改成显式写 0/1**（不再 `unset`）：采纳后 `unset` 会变成"开"，本轮组合就不再由脚本
   决定。自检也改读 `packed_qkv_effective`（eligible 却没装 ⇒ 报错，比旧版更强）。
4. **A/B 脚本加 `ENV_OFF` + fail-closed**：采纳后若不给 off 臂一个显式 `=0`，两臂跑同一实现，
   会静默量出"0% 收益"——比 VOID 更坏，所以直接拒绝（已用翻转默认的临时副本验证过拒绝路径）。
5. 测试改成**对着 `FUSION_DEFAULTS` 断言**，并新增 `packed_qkv_applicable` 的用例
   ⇒ 采纳那天只改默认值，测试不用改。

## 5. S2 优化什么：预注册规则（刷新后机械执行）

1. 从刷新后的 `EXP-p4c-01__bit_width=w8a16_attn=kernel_ctx=1024` 取 `bottleneck.top_kernels`；
2. 每项 `gap = 实测 − 必要字节/1560.3 GB/s`（必要字节由模型形状固定，F1/F2 不改变它）；
3. 只留 `gap ≥ 30 µs`；`可捕获量 = gap × 捕获率`（位精确延迟消除 0.9 / 配置改善 0.3 /
   需精度门 0.5 且先过门）；
4. 选最大者可，单项**不得与其它项同轮混测**。

**按刷新前的 payload 预演（仅用于说明规则会选谁）**：KV 写回（`index_copy` ×32 + `cat` ×32）
≈109 µs × 0.9 = **98 µs** > `gate_up` 94×0.3 = 28 > `down_sum` 83×0.3 = 25 >
`lm_head` 127×0.5 = 63（需门）> 残差 add 48×0.9 = 43。

⇒ **S2 = F4：KV 直写**（RoPE 后直接写 `StaticCache`，去掉那 64 次 launch），做成开关
（`LEMOQ_KV_DIRECT_WRITE`，默认关），K1 位精确 + 独立进程 A/B 过线才翻默认；一轮做不完就留成
"已实现未采纳"的候选（F2 的先例）。卡住则退到 **F3 残差 epilogue**（48 µs，低风险）。
**S3 候选**：`lm_head` 量化成 w8（≈63 µs，需新开一行 `GATE_CITATIONS`，属新实验，单独确认）。
